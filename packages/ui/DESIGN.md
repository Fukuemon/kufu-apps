# Kufu のデザインシステム

Kufu の画面を作る人とコーディングエージェントが、画面とコンポーネントのコードを書く前に読む文書。`packages/ui` のトークンとコンポーネントの使い方と、アクセシビリティの基準を決める。  
値と規則はデジタル庁デザインシステム（DADS）を元にし、Kufu の色、書体、ロゴ、装飾の語彙を残している。規則の基準はこの文書と、下の「話題ごとの文書」の 3 つの文書である。  
出典と、構成を決めた理由の ADR は次のとおり。

- 出典: [デジタル庁デザインシステム](https://design.digital.go.jp/dads/)
- ADR-0018: [トークンを、Kufu の色と DADS の値を持つプリミティブトークン、セマンティックトークン、テーマ変数の 3 つの層にし、shadcn の語彙をやめる](../../docs/adr/0018-design-tokens-three-layers.md)
- ADR-0020: [packages/ui のコンポーネントを、ネイティブの要素と clsx で書いた Base と Case にし、shadcn と Base UI を外す](../../docs/adr/0020-ui-components-native-elements.md)
- ADR-0023: [packages/ui の Storybook をカタログの本体にし、corporate-site の Storybook を画面のカタログとして並べて公開する](../../docs/adr/0023-storybook-catalog.md)
- ADR-0025: [Kufu の色、書体、ロゴ、装飾の語彙を残し、状態の色、フォーカス、文字の最小の大きさ、押せる領域を DADS に合わせ、見出しの上のラベルを日本語だけにする](../../docs/adr/0025-kufu-identity-japanese-labels.md)

トークンとコンポーネントの見た目は、カタログ（Storybook）で見る。ローカルでは `pnpm storybook:ui` で開く。  
カタログは GitHub Pages に公開している。公開先の URL は、配信の基盤が決まった後に `context/project.yml` の `design_system.catalog_url` に書く。

## 話題ごとの文書

デザインシステムの文書は、この文書と、次の 3 つの文書でできている。  
**画面とコンポーネントのコードを書く前に、この文書と 3 つの文書を全て読む。** この文書だけを読むと、トークンの使う場面と、コンポーネントの使い方と状態を知らないまま書くことになる。

| 文書                                             | 持つ規則                                                                           |
| ------------------------------------------------ | ---------------------------------------------------------------------------------- |
| [トークン](design/tokens.md)                     | セマンティックトークンの使う場面、テーマ、文字、レイアウト、角丸、影、動き         |
| [コンポーネントとパターン](design/components.md) | コンポーネントごとの使う場面、変種、状態、内容の制約、キーボードの操作と、パターン |
| [カタログ](design/catalog.md)                    | カタログのページ、題の決め方、カタログに載せてよいもの                             |

## 元にしたデザインシステムとの関係

元にしたデザインシステムは DADS である。DADS が使う側に任せる値には Kufu の選択を、DADS が変えないとする要件には確認の方法を書く。

| 項目                   | DADS の扱い                                                             | Kufu                                                                                                                                                  |
| ---------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 主の色                 | 使う側がキーカラーを選ぶ。主要な背景とのコントラストは 4.5:1 以上にする | `primary` に Kufu の teal を当てる。どの段を指すかは `packages/ui/src/tokens/semantic.css` にある                                                     |
| 余白の段               | 絶対の値を決めない。使う側が基準の単位を選び、その倍率の段を決める      | Tailwind のデフォルトの段（1 段 4px）で書く。規則は原則 `SPACING-SCALE` と、[トークンの文書](design/tokens.md#レイアウト角丸影動き)にある             |
| コントラスト           | 変えない。WCAG 2.2 の AA を満たす                                       | 確認: 「アクセシビリティ」の、文字のコントラストと文字でないもののコントラストの行                                                                    |
| フォーカスの表示       | 変えない。Yellow-300 と黒の 2 重の表示にする                            | `focus-ring` だけを使う。確認: 原則 `FOCUS-ONE`                                                                                                       |
| 状態の色相と意味の対応 | 変えない。状態の色相を、意味と対応させる                                | エラーの `danger` を、DADS の赤の階調に当てる。成功と注意の色は置いていない（「決まっていない選択」）。確認: レビューで `semantic.css` の参照先を見る |

- 出典: [DADS のカラー](https://design.digital.go.jp/dads/foundations/color/)
- 出典: [DADS の余白](https://design.digital.go.jp/dads/foundations/spacing/)

### Kufu の見た目として残すもの

Kufu の色、書体、ロゴ、装飾の語彙は、DADS に合わせずに残す。残すものと使う場所は次のとおり。

| 残すもの     | 内容                                                                                                     | 使う場所                                               |
| ------------ | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 色           | teal と寒色のグレーの値                                                                                  | 主の操作と強調に teal、面と文字と線にグレー            |
| 見出しの書体 | Noto Serif JP の 600                                                                                     | 見出し、経営理念、ブランド名                           |
| 本文の書体   | Noto Sans JP                                                                                             | 本文、リード、UI の文字、見出しの上の和文のラベル      |
| ラベルの書体 | Geist Mono。letter-spacing を広めにする                                                                  | 番号、値の種類のラベル（Tel、Fax、E-mail）、連絡先の値 |
| ロゴ         | 今のマークと favicon                                                                                     | ヘッダー、favicon                                      |
| 装飾の語彙   | 4px の角丸、1px の罫線、ウォーターマークの数字、写真への色の被せ、写真の上のパネル、1 つのトーンの暗い面 | section の面と写真                                     |

- ADR-0025: [Kufu の色、書体、ロゴ、装飾の語彙を残し、状態の色、フォーカス、文字の最小の大きさ、押せる領域を DADS に合わせ、見出しの上のラベルを日本語だけにする](../../docs/adr/0025-kufu-identity-japanese-labels.md)
- 残すものを変える案は、運営者が決める。
- teal のアクセントは、主の操作と強調に使う。面積を絞り、信頼感を優先する。

DADS の指針から外れる規則は、この節に並べない。その規則を持つ場所に、DADS が求めることと外れる理由を書いている。

| 外れる点                                       | 規則と理由のある場所                                                                          |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 主の色とグレーが、DADS の階調の値でない        | [トークンの文書](design/tokens.md#色)の「色」                                                 |
| 見出しが明朝で、ラベルが Geist Mono である     | [トークンの文書](design/tokens.md#文字)の「文字」                                             |
| 12px の文字のスタイルが 1 つある               | 原則 `TEXT-MIN-SIZE` と、[トークンの文書](design/tokens.md#文字)の「文字」                    |
| ウォーターマークの数字のコントラストが低い     | [トークンの文書](design/tokens.md#色)の「色」                                                 |
| 入力欄の誤りの枠、hover の枠、無効の欄の見た目 | [コンポーネントの文書](design/components.md#textinput-と-textarea)の「TextInput と Textarea」 |

## 画面を作るときの原則

原則には ID を付ける。ID は一度付けたら変えない。各原則の「確認」は、守られているかを確認する方法である。  
`pnpm check:design` は、corporate-site と `packages/ui` のコードを読み、`pnpm check` と CI でも流れる。

- `COLOR-TOKEN`: 色、文字、角丸、影、動きは、テーマ変数のユーティリティだけで書く。色の値とプリミティブトークンの名前を、画面のコードに直に書かない。
  - 確認: 色の値とプリミティブトークンの名前は、チェック（`node scripts/check-raw-values.mjs`）で見る。文字、角丸、影、動きの時間と遅れの値は、レビューで見る。アニメーションと緩急の任意値は、`MOTION-TOKEN` のチェックで見る。
- `STATE-NOT-COLOR-ONLY`: 状態を色だけで伝えない。エラーと注意には、文と印を色と一緒に出す。
  - 確認: レビューで、色を見分けられない人がエラーの場所と内容を読み取れるかを見る。
    - 良い例: 入力の誤りの欄に、赤い枠と一緒に誤りの文を出す（`FormField` の `error`）。
    - 悪い例: 必須の欄を、印の文字を出さずに見出しの色だけで示す。
- `TEXT-MIN-SIZE`: 14px より小さい文字を使わない。本文と操作の文字は 16px にし、14px は補足だけに使う。文字の大きさは、トークンの文書の「文字」の表のユーティリティだけで書く。Tailwind のデフォルトの名前（`text-sm`、`text-base` など）と、任意値（`text-[0.8125rem]`、`text-[clamp(...)]`）は書かない。
  - 例外: 12px の `eyebrow` だけを置く。DADS は 14 CSS px 未満を原則として認めない。`eyebrow` は、番号と、値の種類のラベル（Tel、Fax、E-mail）だけに使う。どちらも値の隣に置く短い欧文と数字で、文として読ませないため、外す（[ADR-0025](../../docs/adr/0025-kufu-identity-japanese-labels.md)）。文、操作の文字、和文のラベルと補足には使わない。
  - 確認: `pnpm check:design` の中の `node scripts/check-utilities.mjs --doc packages/ui/DESIGN.md`。`eyebrow` の使い道は、レビューで見る。
- `PRIMARY-ACTION-ONE`: 主のボタンは、1 つの画面かダイアログに 1 つまでにする。
  - 確認: レビューで、画面の主の操作が 1 つに決まるかを見る。ヘッダーの導線のように、全てのページに共通の領域のボタンを数えるかは、「決まっていない選択」にある。
    - 良い例: 問い合わせのフォームで、送信のボタンだけを塗りのボタンにする。
    - 悪い例: 一覧の項目ごとに、塗りのボタンを置く。
- `FOCUS-ONE`: フォーカスの表示は 1 つのユーティリティ（`focus-ring`）だけで付け、コンポーネントごとに色や太さを変えない。リンク、ボタン、入力欄、`summary`、`tabindex` を付けた要素のように、操作できる要素の全てに付ける。表示は DADS の黒の outline と Yellow-300 の影の 2 重で、DADS が変えないとする要件である（[ADR-0025](../../docs/adr/0025-kufu-identity-japanese-labels.md)）。`focus`、`focus-visible`、`focus-within` の変種、`outline` のユーティリティ、フォーカスのトークンの色（`focus-outline`、`focus-halo`）を、ほかに書かない。
  - 確認: `pnpm check:design` の中の `node scripts/check-utilities.mjs --doc packages/ui/DESIGN.md`。操作できる要素に `focus-ring` が付いているかは、レビューで見る。
- `TARGET-SIZE`: 押せる領域は 44×44 CSS px 以上にする。WCAG 2.2 の AA（2.5.8）の 24×24 より厳しい、AAA（2.5.5）の値を選んでいる。見た目を小さくするときは、見た目の外に押せる領域を広げる。
  - 確認: `packages/ui` の押せるコンポーネントの story の play が、描画した幅と高さを `expectTargetSize` で確認する。対象は `Button`、`LinkButton`、`TextInput`、`Select`、`Textarea` で、関数は `packages/ui/src/test/target-size.ts` にある。
  - play は `pnpm --filter @kufu/ui vrt:capture` と CI の vrt-story-ui で流れる。カタログのアクセシビリティの自動チェックは、押せる領域の大きさを確認しない。corporate-site の画面で作る押せる要素は、レビューで見る。
- `SPACING-SCALE`: 余白は、トークンの文書の「レイアウト、角丸、影、動き」の表の余白の段のユーティリティだけで書く。任意値（`p-[13px]` のような書き方）を書かない。
  - 確認: レビューで見る。余白の任意値を止めるチェックの規則は、まだ無い。今のコードに残る任意値の扱いは、「決まっていない選択」にある。
  - 入力欄と、その見出し、補足の文、誤りの文の間は、`gap-2`（8px）以上にする。フォーカスの表示は欄の外へ 6px 広がり、間が狭いと近くの文字に重なる。`FormField` は、この間を `gap-2` で持つ。
    - 確認: `FormField` を使わない欄は、レビューで、欄と近くの文字の間が `gap-2` 以上かを見る。
- `LAYOUT-OVERFLOW`: レイアウトのブレークポイントの幅ごとに、ページの横方向のオーバーフローを出さない。長い文字とデータの多い状態でも出さない。
  - 確認: レビューで、route の VRT が撮った狭い幅と広い幅の画像と、描画した画面を見る。ページの全体の幅を機械で確認するテストは、まだ無い。
- `MOTION-TOKEN`: アニメーションと緩急は、トークンの文書の「レイアウト、角丸、影、動き」の表の動きのユーティリティだけで書く。任意値（`animate-[ping_1s_infinite]` のような書き方）を書かない。任意値はテーマ変数を通らないので、時間と緩急がトークンにそろわない。
  - 確認: レビューで見る。アニメーションと緩急の任意値を止めるチェックの規則は、まだ無い。今のコードに、この任意値は無い。
- `MOTION-REDUCE`: 利用者が OS で動きを減らす設定（`prefers-reduced-motion: reduce`）にしたときは、位置、大きさ、回転を動かすアニメーションと遷移、スクロールに合わせた動きを止める。残すのは、状態の変化を伝える短い透明度の変化だけにする。機能に欠かせない動きは、今は無い。WCAG 2.2 の AA に無い、AAA（2.3.3）の基準を選んでいる。止め方はテーマ変数のファイル（`theme.css`）の 1 か所に置き、画面のコードに設定ごとの条件を書かない。
  - `theme.css` は、設定が `reduce` のとき、全ての要素のアニメーションを止め、遷移を透明度だけにし、滑らかなスクロールを止める。
  - 例外: JavaScript が動かすものは CSS で止められないので、JavaScript で設定を読む。
    - 今は 2 か所で、トップのカルーセルの自動の流れ（`requestAnimationFrame`）と、section を表示するきっかけ（`IntersectionObserver`）である。
    - どちらの行にも、`design-system-allow` と理由を書いている。
  - 確認: `pnpm check:design` の中の `node scripts/check-utilities.mjs --doc packages/ui/DESIGN.md` が、設定の条件を止める。
    - 止めるのは、画面とコンポーネントのコードの `motion-reduce:`、`motion-safe:` の変種と、`prefers-reduced-motion` の条件である。
    - 止め方が動きを止めるかは、レビューで `theme.css` を見る。

| ID                     | 確認の方法                       | チェックが見ないもの                                                                                                                 |
| ---------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `COLOR-TOKEN`          | `check-raw-values.mjs`           | 文字、角丸、影、動きの時間と緩急の値                                                                                                 |

| `PRIMARY-ACTION-ONE`   | レビュー                         |                                                                                                                                      |

## 画面を作るときの手順

画面とコンポーネントのコードを書く人は、この順に進め、受け入れ条件を満たしたら終える。

### 順

1. 参照先の表、トークンの文書、コンポーネントの文書、カタログから、使うパターン、コンポーネント、トークンを探す。合うものがなければ、画面のコードで作らず、デザインシステムに足すかを尋ねる。
2. テーマ変数のユーティリティと、このデザインシステムのコンポーネントだけで書く。
3. 使ったコンポーネントの状態のうち、画面で起きるものを作る。
4. 下の「流すコマンド」を、表の順に流す。
5. 描画した画面を、トークンの文書のブレークポイントの幅ごとに、通常の面と暗い面の両方で見て、横方向のオーバーフローを確認する。撮った画像はレビューで見る。
6. チェックが通らなければ直し、手順 4 から流し直す。チェックの出力を見て自分で直すのは、2 回までにする。
   - 2 回直しても通らないか、違反の数が減らないときは、直すのをやめて止まる。最後に全てのチェックが通ったコミットに、通らない変更を混ぜない。通らない変更は、コミットせずに差分として報告に添える。
   - 全てのチェックが通ったコミットが無いときは、作業を始めたときのコミットを代わりにし、そのときに既に通らなかった原則の ID を報告に書く。
7. 下の「報告の形」で報告する。止まったときは、最後に通ったコミットの SHA と、通らないまま残った原則の ID を書く。

### 流すコマンド

表の順に流す。前のコマンドが失敗したら、後のコマンドは流さずに「見ていない」と報告する。上の 3 行は、`pnpm check:design` がまとめて流す。

| コマンド                                                                                                                   | 見るもの                                                                 | 原則の ID                                                                                       |
| -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| `node scripts/check-contrast.mjs` と、暗い面の条件で流す同じスクリプト（CONTRIBUTING.md の「デザインシステムを直すとき」） | セマンティックトークンの組のコントラスト比                               |                                                                                                 |
| `node scripts/check-raw-values.mjs`                                                                                        | 画面のコードの色の値とプリミティブトークンの名前                         | `COLOR-TOKEN`                                                                                   |
| `node scripts/check-utilities.mjs --doc packages/ui/DESIGN.md`                                                             | 画面のコードの、原則に反するユーティリティ。規則の ID がこの文書にあるか | `TEXT-MIN-SIZE`、`FOCUS-ONE`、`MOTION-REDUCE`。`SPACING-SCALE`、`MOTION-TOKEN` の規則はまだ無い |
| `pnpm --filter @kufu/ui vrt:capture`                                                                                       | `packages/ui` の story の play と、a11y のアドオンの違反                 | `TARGET-SIZE`                                                                                   |

- 静的なファイル用のトークンの CSS は生成していないので、生成物のずれのチェックは無い。
- 基準の画像と比べる確認（VRT）のコマンド、撮る環境、基準の画像の撮り直し方は、[context/testing.md](../../context/testing.md#vrt) にある。意図して見た目を変えたときは、基準の画像を撮り直し、同じ変更に入れる。

### 受け入れ条件

- [ ] 「流すコマンド」が全て終了コード 0 で終わった
- [ ] 「確認の方法」がレビューの原則を、描画した画面で見た
- [ ] 幅とテーマごとに撮った画像を、レビューで見た

### 報告の形

原則の ID ごとに、次の 5 つの状態のどれかで報告する。チェックの終了コードが 0 でも、レビューの原則を通ったにしない。

| 状態           | 意味                                                                                 |
| -------------- | ------------------------------------------------------------------------------------ |
| 通った         | チェックが流れ、基準を満たした                                                       |
| 通らない       | 違反の証拠がある。場所と、出たチェックの出力を添える                                 |
| レビューで見る | 描画した画面かコードはあるが、判断はレビューの人がする                               |
| 見ていない     | 確認の規則、チェック、証拠のどれかが無い。前のコマンドの失敗で流していないものも含む |
| 対象外         | 作業の範囲から外れる。理由を添える                                                   |

報告の冒頭に、どのコードと文書を見た結果かを書く。

| 項目                               | 書くこと                                                                                                                                                                                  |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 対象のコミット                     | チェックを流したときの `git rev-parse HEAD` の SHA                                                                                                                                        |
| コミットしていない変更             | なし、またはあり。ありのときは、変えたファイルの一覧（`git status --short` の出力）                                                                                                       |
| デザインシステムの文書のバージョン | この文書と 3 つの文書のどれかを最後に変えたコミットの SHA（`git log -1 --format=%H -- packages/ui/DESIGN.md packages/ui/design`）。どれかにコミットしていない変更があれば、そのことも書く |

## アクセシビリティ

WCAG 2.2 の AA を基準にする。押せる領域と、動きを減らす設定は、AAA の値を選んでいる。

| 項目                         | 基準                                                                                                                                                                                | 確認の方法                                                                                                                                                              |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文字のコントラスト           | 4.5:1 以上                                                                                                                                                                          | セマンティックトークンの組は `node scripts/check-contrast.mjs`（通常の面と暗い面）。`packages/ui` の story は、a11y のアドオンの違反でテストが失敗する                  |
| 文字でないもののコントラスト | 入力欄と押せる枠の境界、フォーカスの表示が 3:1 以上                                                                                                                                 | `node scripts/check-contrast.mjs` の、文字でないものの組。a11y のアドオンは、枠の色を確認しない                                                                         |
| フォーカスの見え方           | 全ての操作できる要素で、フォーカスの表示を出す                                                                                                                                      | `check-utilities.mjs` とレビュー（`FOCUS-ONE`）                                                                                                                         |
| ターゲットの大きさ           | 44×44 CSS px 以上。AA の 2.5.8 の 24×24 より厳しい、このプロダクトの選択（AAA の 2.5.5）                                                                                            | `packages/ui` の story の play（`TARGET-SIZE`）                                                                                                                         |
| キーボードの操作             | コンポーネントの文書のとおりに動く                                                                                                                                                  | レビュー。`packages/ui` のコンポーネントはネイティブの要素で書き、キーボードの操作はブラウザが持つ。corporate-site の素の script の操作の UI は、レビューで操作して見る |
| 入力の誤りの伝え方           | 欄ごとの誤りの文は `aria-describedby` で欄に結び付け、`role="alert"` を付けない。送った後は最初の誤りの欄へフォーカスを移す。送れなかったときの文だけを `role="alert"` で読み上げる | 欄と誤りの文の結び付けは、`FormField` の story の play。送った後のフォーカスと、送れなかったときの文は、フォームを作るときにテストを足す。今は確認の方法が無い          |
| 動きを減らす設定             | 設定が `reduce` のとき、位置、大きさ、回転を動かすアニメーションと遷移、スクロールに合わせた動きを止める。このプロダクトの選択（AAA の 2.3.3）                                      | `check-utilities.mjs` とレビュー（`MOTION-REDUCE`）                                                                                                                     |

## 決まっていない選択

DADS にも、デザインシステムの文書の規則にもない選択を、選択、案、理由で書く。決まったら規則のセクションへ移し、ここから消す。

- 本文の中のリンクの色と下線、訪問済みの色: 案は、リンクの文字を `primary` にし、下線を付ける。今は、リンクが文字の色を引き継ぎ、下線を持たない。DADS は、色だけでリンクを示さないことを求める。
- 成功と注意の状態の色: 案は、成功を DADS の緑、注意を DADS の橙の階調から、使うコンポーネントを足すときに置く。今は、使うコンポーネントが無いので置いていない。使っていない名前を残さない規則による。
- 余白の任意値の扱い（`SPACING-SCALE`）: 案は、任意値を止める規則を `check-utilities.mjs` に足し、今の任意値を段に直す。今のコードには、余白の任意値が `Button` と `Tag` に 1 つずつ、corporate-site の section に 2 つある。[context/conventions.md](../../context/conventions.md#スタイリングの共有と書き方) は、大きさと余白の任意値を書いてよいとしている。
- アニメーションと緩急の任意値のチェック（`MOTION-TOKEN`）: 案は、任意値を止める規則を `check-utilities.mjs` に足す。今のコードに違反は無いが、規則が無いので、足されても止まらない。
- 主のボタンの数え方（`PRIMARY-ACTION-ONE`）: 案は、ヘッダーのような全てのページに共通の領域のボタンを数えず、ページの本文の中で 1 つにする。今は、ヘッダーと、ページの最初の画面や section の両方に、問い合わせへの導線の塗りのボタンがある。
- 無効のボタンの、押せない理由の示し方: 案は、押せるようにする条件の文をボタンの近くに出し、`aria-describedby` でボタンに結び付ける。今の画面に、無効のボタンは無い。
- 面の並べ方と teal を使う場所を、元の規則にコードをそろえるか: 元の規則は 2 つある。明るい面は、`surface-canvas` と `surface-subtle` を交互に置く。teal は、CTA のボタン、番号、見出しの上のラベル、理念の強調の語だけに使う。今のトップの面は、canvas、surface、surface、subtle、canvas の順である。teal は、連絡先のラベル、パンくず、リンクの hover にも使っている。
- 和文の短いラベルの書体: 案は、和文のラベルを `font-sans` にし、`font-mono` を欧文と数字だけに使う。今は、必須と任意の印と、`DefinitionRow` の `compact` の見出しが、和文を `font-mono` で出している。
- `Divider` と余白の使い分け: 案は、内容のまとまりが変わる所にだけ `Divider` を置き、同じまとまりの中の間は余白で区切る。今は、`Divider` を使う画面が無い。
- ページの横方向のオーバーフローを機械で確認するか（`LAYOUT-OVERFLOW`）: 案は、E2E のテストで、ブレークポイントの幅ごとにページの幅を確認する。今は、レビューで見る。
