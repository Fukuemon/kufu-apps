# ADR-0028: E2E のテストのコードを層に分けて書き、ページ単位の Page Object をやめる

## Status

承認

## Context

- ADR-0027 は、play と E2E の役割、ページ単位の Page Object、locator の使い分け、E2E が受け持つジャーニーを決めた。
  - ADR-0027: [play テストと E2E の役割を分け、Page Object と locator の規約を定める](0027-ui-test-structure-policy.md)
- E2E は、`e2e/corporate-site/smoke.spec.ts` の 5 件と、3 つの route の Page Object のクラスである。3 本のジャーニーは、まだ書いていない。
- agent-harness のパッケージ e2e を `apm.yml` に入れた。パッケージのスキル write-e2e-test は、テストのコードを次の層に分ける。テスト用のクラスは作らず、ページを引数に取る関数を並べる。

  | 層           | 持つもの                                           |
  | ------------ | -------------------------------------------------- |
  | `specs/`     | 何を確認するか。確認はここに書く                   |
  | `setup/`     | テストデータを作る手順                             |
  | `screens/`   | 3 本以上の spec が使う、画面を開く操作             |
  | `widgets/`   | 処理の完了が DOM に出ない UI の操作と待ち          |
  | `selectors/` | testid を付けられない要素の指し方                  |
  | `fixtures/`  | 環境変数、待つ時間の名前、撮影の字幕の関数などの値 |

- パッケージの書き方の規則は、role、label、文言、CSS のセレクタで要素を拾う書き方を、`selectors/` の外で止める。spec として扱うのは、名前が `.e2e.ts` で終わるファイルである。
- 規則を今の E2E に当てると、指摘は 11 件で、すべて Page Object の中の要素の拾い方だった。内訳は、role で拾う 5 件、CSS のセレクタで拾う 4 件、文言で拾う 2 件である。`smoke.spec.ts` の指摘は 0 件だった。
- corporate-site は静的なサイトで、ログイン、テストデータ、API を持たない。
- React の island は 0 件で、問い合わせフォームは実装していない。

## Decision

ADR-0027 の 4 つの判断のうち、Page Object の判断を変える。ほかの 3 つは、変えずに引き継ぐ。  
この決定は、ADR-0027 を置き換える。

### 1. play テストの対象は packages/ui に限る

- island の対象の基準は、island ができるとき（問い合わせフォームの実装）に決める。
- Astro の静的なコンポーネントは、E2E で確認する。

### 2. E2E のテストのコードを層に分け、Page Object のクラスを作らない

- テストのコードは、E2E のテストのディレクトリの `tests/` の下に、層ごとに置く。
- 最初に置く層は、`specs/`、`selectors/`、`fixtures/` の 3 つにする。
  - `specs/`: `<機能>/<振る舞い>.e2e.ts` に置く。確認と、1 本か 2 本の spec だけが使う操作を書く。
  - `selectors/`: testid を持たない要素の指し方を、ページを引数に取る関数で置く。
  - `fixtures/`: 環境変数の読み取り、待つ時間の名前、撮影の字幕の関数を置く。
- `screens/` は、同じ「画面を開く、モードを変える」を 3 本目の spec が要ったときに足す。
- `setup/` と `widgets/` は、テストデータを作る機能と、完了が DOM に出ない UI ができるまで作らない。
- 複数の route をまたぐ手順は、spec に書く。
- テストの名前は、「{条件}の場合、{期待}であること」にする。

理由は 2 つある。

- 書き方の規則を lint として掛けられる。規則が止める拾い方は、`selectors/` に集まる。
- 3 つの route と 3 本のジャーニーの規模では、ページごとのクラスに集めるより、spec に手順を書く方が読む場所が少ない。

### 3. locator は用途で使い分け、testid を持たない指し方を selectors/ に置く

- セクションやページの領域は、`data-testid` で拾う。spec に直接書いてよい。
- 領域の中の操作の対象（ボタン、リンク、入力欄）は、role と名前で拾う。拾う関数は `selectors/` に置く。
- ヘッダーとフッターで文言が重なる操作の対象は、`data-testid` で拾う。
- 表示の内容の確認に使う文言と、DOM の件数を数える指し方も、`selectors/` に置く。
- production の markup は、この決定のためには変えない。

操作の対象を role と名前で拾い続けるのは、リンクやボタンの名前の崩れを E2E で検出するためである。

### 4. E2E が受け持つジャーニーは、route をまたいだ到達にする

- 1 つのコンポーネントの中で閉じる操作は、play が受け持つ。
- ジャーニーは次の 3 本で、回帰の E2E として `specs/` に書く。
  - **回遊**: `/` から `/products`、カテゴリの検索（URL に検索の条件が残る）を経て、`/contact` に到達できる。
  - **ナビゲーション**: ヘッダーとフッターのリンクと、モバイルのナビの開閉から、各 route へ到達できる。
  - **JS 無効時**: JavaScript を無効にしても 3 つの route の主なコンテンツが表示され、問い合わせ先（電話、メール）に到達できる。
- 問い合わせフォームの送信は実体がないので、island を実装するときに足す。

## Considered Options

| 選択肢                                                                                                           | 強み                                                                                                   | 弱み                                                                                        |
| ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| **採用:** 層に分け、Page Object のクラスをやめる。操作の対象は role と名前で拾い、拾う関数を `selectors/` に置く | 書き方の規則を lint として掛けられる。production の markup を変えない。名前の崩れを E2E で検出し続ける | 3 つの Page Object と smoke を書き直す。操作の対象を testid で拾うスキルのデフォルトと違う  |
| 層に分け、操作の対象にも `data-testid` を足して testid だけで拾う                                                | スキルのデフォルトと同じになる。`selectors/` がほぼ空になる                                            | production の markup に testid を足す。リンクやボタンの名前が変わっても E2E が落ちない      |
| Page Object のクラスを残し、規則が止める拾い方だけを `selectors/` に移す                                         | 書き直す量が少ない                                                                                     | クラスと関数の 2 つの形が並ぶ。スキルの書き方と合わず、ほかのリポジトリと読み方がそろわない |
| Page Object を残し、書き方の規則を掛けない                                                                       | 何も変えない                                                                                           | 規則に反する書き方を lint で見つけられない                                                  |

## Consequences

### Positive

- E2E のコードの書き方を、lint で確認できる。
- 待ち方、確認の方法、名前の付け方を、buddy と同じスキルで読める。
- role や文言での拾い方が `selectors/` に集まり、markup を変えたときに直す場所が 1 か所になる。

### Negative

- 今の 3 つの Page Object と `smoke.spec.ts` を書き直す。
- 操作の対象を role と名前で拾うので、文言を変える変更で E2E が落ちる。
- 層のディレクトリの名前は規則が読むので、変えられない。
- play の対象が `packages/ui` に限られるので、Astro の側の interaction は E2E に頼る。
