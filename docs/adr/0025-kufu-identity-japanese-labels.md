# ADR-0025: Kufu の色、書体、ロゴ、装飾の語彙を残し、状態の色、フォーカス、文字の最小の大きさ、押せる領域を DADS に合わせ、見出しの上のラベルを日本語だけにする

## Status

承認

## Context

DADS の考え方でデザインシステムを作り直すときに、Kufu の見た目として何を残し、何を DADS に合わせるかを決める必要がある。

- 運営者は、Kufu の感じを残すと決めた。Kufu の色、書体、ロゴは変えない。変える案は、運営者が決める。
- 今の表現の基準は、corporate-site の Design Doc の「トーンとマナー」にある。
  - 色: 寒色のグレーを基調にし、teal をアクセントにする。フッターと強い CTA の帯は、1 つのトーンの暗い面にする。
  - 書体: 見出しは Noto Serif JP の 600、本文は Noto Sans JP、eyebrow とラベルと番号は Geist Mono で、letter-spacing を広めにする。
  - 装飾: 4px の角丸、1px の罫線、大きなウォーターマークの数字、写真への色の被せ、写真の上のパネル。
- トークンは、Kufu の色をプリミティブトークンに残し、状態とフォーカスの色、文字、角丸を DADS からコピーする。
  - ADR-0027: [トークンを、Kufu の色と DADS の値を持つプリミティブトークン、セマンティックトークン、テーマ変数の 3 つの層にし、shadcn の語彙をやめる](0027-design-tokens-three-layers.md)
- DADS は、次のことを定めている。
  - キーカラーは使う側が選ぶ。主要な背景とのコントラストは 4.5:1 以上にする。
  - 状態の色相と、フォーカスの表示（Yellow-300 と黒の 2 重）は変えない。
    - 出典: [DADS のカラー](https://design.digital.go.jp/dads/foundations/color/)
  - 書体は Noto Sans JP と Noto Sans Mono を勧める。システムの書体を使うことは制限しない。本文と UI の文字は 16 CSS px 以上を基準にし、14 CSS px は限られた用途に使い、14 CSS px 未満は原則として認めない。
    - 出典: [DADS のタイポグラフィ](https://design.digital.go.jp/dads/foundations/typography/)
  - 押せる領域は 44 CSS px 以上にする。
    - 出典: [DADS のボタン](https://design.digital.go.jp/dads/components/button/)
- 今の画面には、14px より小さい文字が約 70 か所ある。11px が 24、13px が 18、12px が 13、10px が 10 である。多くは mono の eyebrow とラベルで、本文にも 13px と 13.5px がある。
- 今のフォーカスの表示は、teal の ring である。
- `/contact` の入力欄の枠は、面に対するコントラストが 1.44〜1.53 で、3:1 に届かない。
- 要求の受け入れ条件は、本文とボタンと入力欄のコントラストが WCAG 2.2 の AA を満たすことと、DADS から外れる箇所の理由を文書に書くことである。
- 運営者は、ページのデザインを見直すときに、見出しの上の英字のラベルが日本の企業向けのサイトに要るかを検討するよう求めた。AI が作ったように見える点をなくし、個性は残す方針である。
- ADR-0030 を書いた時点の見出しの上のラベル（eyebrow）は、次のとおり。
  - 英字と日本語の併記: セクションの見出しの「CONSULTATION / ご相談内容」「BUSINESS / 事業内容」「PRODUCTS & MAKERS / 取扱製品・取扱メーカー」「COMPANY / 会社概要」
  - 英字と日本語の併記: 会社概要の中の「PHILOSOPHY / 経営理念」「PROFILE / 基本情報」「MESSAGE / 代表挨拶」「ACCESS / アクセス」
  - 英字だけ: 最初の画面、事業の行、取扱製品とお問い合わせの見出し、索引、フッター、ナビの添え字
  - 番号と値の種類: セクションとカテゴリの番号、「Tel」「Fax」「E-mail」
- 併記のラベルの和文は、「経営理念」のように、見出しにない情報を持つことがある。英字の側は、見出しと同じ意味である。
- 日本の機械工具の商社、加工、設備工事、建設の会社のサイトを 19 開いて確認した。英字を主にするものが 7、日本語を主にして英字を添えるものが 4、日本語だけが 6、混在が 2 だった。標本が少なく、選び方も偏っているので、割合としては一般化できない。
- AI が作ったように見える型を挙げる記事は、見出しの上の小さいラベルを全ての見出しに繰り返すことと、情報を足さないラベルを挙げている。ラベルは見出しと重なるなら外すよう勧めている。
  - 出典: [Impeccable の型の一覧](https://impeccable.style/slop)
  - 出典: [Brafton の記事](https://www.brafton.com/blog/graphics/weve-seen-this-website-before-ai-design-and-development/)

## Decision

### 1. 残すもの

| 残すもの     | 内容                                                                                                     | 使う場所                                               |
| ------------ | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 色           | teal（`teal-600`、`teal-300`、`teal-900`）と寒色のグレーの値                                             | 主の操作と強調に teal、面と文字と線にグレー            |
| 見出しの書体 | Noto Serif JP の 600                                                                                     | 見出し、経営理念、ブランド名                           |
| 本文の書体   | Noto Sans JP                                                                                             | 本文、リード、UI の文字、見出しの上の和文のラベル      |
| ラベルの書体 | Geist Mono。letter-spacing を広めにする                                                                  | 番号、値の種類のラベル（Tel、Fax、E-mail）、連絡先の値 |
| ロゴ         | 今のマークと favicon                                                                                     | ヘッダー、favicon                                      |
| 装飾の語彙   | 4px の角丸、1px の罫線、ウォーターマークの数字、写真への色の被せ、写真の上のパネル、1 つのトーンの暗い面 | section の面と写真                                     |

- 残すものと使う場所は、デザインシステムの文書に移す。corporate-site の Design Doc の「トーンとマナー」は、移した先へリンクする。

### 2. DADS に合わせるもの

| 項目               | 合わせた後                                                                              | 今                                  |
| ------------------ | --------------------------------------------------------------------------------------- | ----------------------------------- |
| 状態の色           | エラーは DADS の赤の階調にする。成功は緑、注意は橙の階調から、使うときに置く            | shadcn のデフォルトの `destructive` |
| フォーカスの表示   | 黄と黒の 2 重の表示にし、1 つのユーティリティで付ける                                   | teal の ring                        |
| 文字の最小の大きさ | 本文と操作の文字は 16px、補足は 14px にする                                             | 本文に 13px と 13.5px がある        |
| 文字の大きさの段   | DADS の文字の大きさの段から、今の値に最も近い段を選び、用途の名前の付いたスタイルにする | 任意の値が 28 通りある              |
| 入力欄の枠         | 面に対して 3:1 以上にする                                                               | 1.44〜1.53                          |
| 押せる領域         | 44×44 CSS px 以上にする                                                                 | 決めていない                        |

### 3. DADS から外れるもの

外れる点は、理由と一緒に、デザインシステムの文書のその規則の隣に書く。

| 外れる点                                   | DADS が求めること                    | 外れる理由                                                                                                                          |
| ------------------------------------------ | ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| 主の色とグレーが、DADS の階調の値でない    | キーカラーを、同じ色相の階調から選ぶ | Kufu の色を変えない。コントラストは、DADS の指針に頼らず、コントラストのチェックで確認する                                          |
| 見出しが明朝である                         | Noto Sans JP を勧める                | 明朝の見出しが、Kufu の信頼感の表現の中心である。本文と UI の文字は Noto Sans JP にする                                             |
| ラベルが Geist Mono である                 | 等幅は Noto Sans Mono を勧める       | 欧文と数字のラベルの字形が、工業的な印象を作っている。和文を含む文には使わない                                                      |
| 番号と値の種類のラベルが 12px である       | 14 CSS px 未満を原則として認めない   | 番号と、値の隣に置く欧文の短いラベルで、文として読ませない。10px と 11px はやめ、12px の `text-eyebrow` の 1 つのスタイルだけにする |
| ウォーターマークの数字のコントラストが低い | 文字は 4.5:1 以上にする              | 読ませる文字ではなく、面の飾りである。支援技術からは隠す                                                                            |

- 12px のスタイルは `text-eyebrow` の 1 つだけを置く。番号と値の種類のラベルだけに使い、文、操作の文字、和文のラベルと補足には使わない。
- 名前は ADR-0030 で決めた `text-eyebrow` のまま残し、使う場面の説明だけを、この決定に合わせて直す。名前を改めると、トークン、テーマ変数、チェック、約 30 か所の画面のコードを直すことになるためである。
- 文字の大きさを変えた後の画面は、運営者が VRT の baseline を見て決める。

### 4. 見出しの上のラベル

見出しの上のラベルから英字を外し、見出しにない情報を持つ和文のラベルだけを残す。意味を運ぶのは和文の側で、英字を外しても情報は減らないためである。

| 今のラベル                                         | 扱い                                                       | 例                                                           |
| -------------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------ |
| 英字と日本語の併記で、和文が見出しにない情報を持つ | 和文だけを残す                                             | ご相談内容、事業内容、取扱製品・取扱メーカー、経営理念       |
| 英字と日本語の併記で、和文が見出しと同じかほぼ同じ | 外す                                                       | 会社概要、基本情報、アクセス、代表挨拶                       |
| 英字だけ                                           | 外す。新しい文言は足さない                                 | 最初の画面、事業の行、索引、フッター、ナビの添え字           |
| 英字と番号                                         | 番号だけを残す。番号を背面の数字が示す行は、ラベルごと外す | CATEGORY 01、BUSINESS 01 / SALES & SUPPLY                    |
| 番号と値の種類                                     | Geist Mono の 12px で残す                                  | セクションの番号、カテゴリの番号、Tel、Fax、E-mail、TEL、FAX |

- 残す和文のラベルは、Noto Sans JP の 14px（補足の文字のスタイル）で組む。
- ロゴに添えた社名の欧文「FUKUURA」は、ロゴの一部として残す。

## Considered Options

| 選択肢                                                                                                                                                 | 強み                                                                                                                                        | 弱み                                                                                                                                                     |
| ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **採用:** 色、書体、ロゴ、装飾を残し、読む文字とフォーカスと状態の色を DADS に合わせ、見出しの上のラベルは和文だけにし、番号と値の種類だけ 12px を残す | Kufu だと分かる見た目が残る。読む文は DADS の基準を満たす。外れる点が 5 つに絞られる。12px の対象が番号と値の種類に絞られる。情報は減らない | 約 70 か所の文字の大きさが変わる。ラベルのある見出しと、ない見出しができる。Geist Mono の出番が番号と連絡先だけになる。12px の例外を、レビューで見続ける |
| 見出しの上の英字のラベルを今のまま残し、12px にそろえる                                                                                                | 見た目が今と変わらない                                                                                                                      | 見出しと同じ意味の英字を、全ての見出しで読むことになる。AI が作ったように見える型のままである。和文の側の大きさが決まらない                              |
| 見出しの上のラベルを全て外す                                                                                                                           | 見出しだけになり、読む行が最も少ない                                                                                                        | 「経営理念」のように、見出しにない情報を持つラベルも消える。新しい文言を足さない限り、理念の見出しが何の言葉かを示せなくなる                             |
| 全ての文字を 14px 以上にする                                                                                                                           | DADS の基準どおりで、文字の大きさの例外がない                                                                                               | 番号と値の種類のラベルが大きくなり、値との差が縮む。工業的なラベルの印象が最も変わる                                                                     |
| 今の文字の大きさを全て残し、理由を文書に書く                                                                                                           | 見た目が変わらない                                                                                                                          | 10px の文字と 13px の本文が残る。訪問者の読みやすさを説明しにくい                                                                                        |
| フォーカスの表示を teal のまま残す                                                                                                                     | 色の統一感が残る                                                                                                                            | DADS が変えないとする要件から外れる。暗い面で見えるかを、面ごとに確認することになる                                                                      |
| 書体も DADS に合わせ、見出しを Noto Sans JP にする                                                                                                     | 読み込む書体が減る                                                                                                                          | Kufu の書体を変える。運営者の決定と合わない                                                                                                              |

## Consequences

### Positive

- 訪問者は、Kufu のサイトだと分かる見た目のまま、読む文字を 14px 以上で読める。
- キーボードで操作する訪問者は、明るい面と暗い面のどちらでも、同じフォーカスの表示を見分けられる。
- DADS から外れる点と理由が、文書の規則の隣で読める。
- 訪問者は、見出しと同じ意味の英字を読まずに済み、見出しにない情報（経営理念など）だけを和文のラベルで読める。

### Negative

- 文字の大きさ、フォーカスの表示、入力欄の枠を変えるので、route と story の VRT の baseline を撮り直す。
- Kufu の色の組み合わせは、DADS の指針に頼れない。色を足すたびに、コントラストのチェックの組を足す。
- 12px のスタイルが、番号と値の種類のほかに使われていないかを、チェックでは見分けられない。レビューで見る。
- 見出しの明朝と Geist Mono を読み込むので、DADS の書体だけの構成より、書体の読み込みが多い。
- content 層の見出しのラベルの値を、和文だけに直し、英字だけの値を消す。ラベルを外した見出しの並びと、route と story の VRT の baseline を撮り直す。
- `packages/ui/DESIGN.md` と `packages/ui/design/tokens.md` は、ADR-0030 を指し、`text-eyebrow` を見出しに添えるラベルに使うと書いている。見出しの上のラベルを直す実装のタスクで、この ADR に合わせて直す。
