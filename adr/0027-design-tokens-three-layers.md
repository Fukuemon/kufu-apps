# ADR-0027: トークンを、Kufu の色と DADS の値を持つプリミティブトークン、セマンティックトークン、テーマ変数の 3 つの層にし、shadcn の語彙をやめる

## Status

提案

## Context

kufu-apps のデザインシステムを、デジタル庁デザインシステム（DADS）と buddy を参考に作り直す。トークンの持ち方を決める必要がある。

- トークンは、primitive と shadcn の語彙の semantic の 2 層である。
  - ADR-0007: [デザイントークンを primitive と shadcn の語彙の 2 層に分け、tokens、fonts、theme、全量の entry で配る](0007-design-token-architecture.md)
- 運営者は、shadcn と Base UI を外し、shadcn の語彙のトークンを DADS の考え方のセマンティックトークンに置き換えると決めた。Kufu の色、書体、ロゴは変えない。
- shadcn の語彙のユーティリティ（`text-muted-foreground`、`border-border` など）は、corporate-site と `packages/ui` に 260 か所ある。使っていない `--sidebar-*`、`--chart-*`、`--popover` も、名前を消さない規則で残っている。
- corporate-site は、プリミティブトークンの名前のユーティリティ（`text-kufu-gray-200`、`bg-kufu-gray-950` など）を、暗い面で直に書いている。
- 色の値のチェックは `apps/corporate-site/scripts/check-token-usage.mjs` だけで、コントラスト、文字の大きさ、フォーカスの表示を確認する仕組みがない。
- 運営者が保守する buddy と fukuemon.dev は、DADS の `@digital-go-jp/design-tokens` 2.1.0 からコピーした値を、3 つの層で持つ。層は、プリミティブトークン、セマンティックトークン、テーマ変数である。agent-harness のパッケージ design-system のチェックは、この 3 つの層を前提にする。
  - 出典: [buddy の ADR-0013](https://github.com/Fukuemon/buddy/blob/83472b52b3e4e7ecb7c450b4c5bc21fa2025098b/docs/adr/0013-design-system-primitive-tokens.md)
  - 出典: [fukuemon.dev の ADR-0020](https://github.com/Fukuemon/fukuemon.dev/blob/739871f460b490cc9e1361435d4382c739bdddc6/adr/0020-design-tokens-from-dads.md)
- DADS は、キーカラーを使う側が選ぶとし、主要な背景とのコントラストが 4.5:1 以上であることを求める。状態の色相（成功は緑、エラーは赤、注意は黄か橙）と、フォーカスの表示（Yellow-300 と黒の 2 重）は、変えないとしている。
  - 出典: [DADS のカラー](https://design.digital.go.jp/dads/foundations/color/)
- 今の Kufu の色のコントラストは、次のとおり。
  - `gray-900` と `gray-50` は 13.89、`gray-600` と `gray-50` は 5.63、`teal-600` と `gray-50` は 5.96、白と `teal-600` は 6.33 で、文字の 4.5:1 を満たす。
  - 入力欄の枠の `gray-300` は、面に対して 1.44〜1.53 で、3:1 に届かない。
  - `gray-500` の文字は、明るい面で 3.47、暗い面（`gray-950`）で 4.81 である。
- フッターと CTA の帯は、`.surface-inverse` のスコープで semantic の変数を上書きして、暗い面にしている。ダークモードは持たない。
- workspace の package は、ソースを export する。`packages/ui` の `exports` の分け方は、この要求の設計に委ねられている。
  - 出典: [ADR-0026](https://github.com/Fukuemon/kufu-apps/blob/48380362a729fe2d5090af0fa25649d6a95adf75/adr/0026-workspace-package-contract.md)

## Decision

トークンを 3 つの層に分け、`packages/ui/src/tokens/` に置く。画面とコンポーネントのコードは、テーマ変数のユーティリティだけを書く。

| 層                     | ファイル        | 持つもの                                                                                                                                          |
| ---------------------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| プリミティブトークン   | `primitive.css` | 値。Kufu の色（teal、寒色のグレー、白）と motion の値、DADS からコピーした値（状態とフォーカスの色、文字の大きさと行高、角丸、影）                |
| セマンティックトークン | `semantic.css`  | 色の役割の名前。プリミティブトークンを参照する                                                                                                    |
| テーマ変数             | `theme.css`     | Tailwind CSS の `@theme inline`。色はセマンティックトークンだけを参照する。文字、角丸、影、動きはプリミティブトークンを参照し、用途の名前を付ける |

### 1. プリミティブトークンは、Kufu の色と DADS の値の 2 つの出どころを持つ

- teal、寒色のグレー、白は、今の `--kufu-<色>-<段>` の値を変えずに持つ。Kufu の色を変えないためである。
- 状態の色（エラーの赤、成功の緑、注意の橙）、フォーカスの色（Yellow-300 と黒）、文字の大きさと行高、角丸、影は、DADS の `@digital-go-jp/design-tokens` 2.1.0 の値をコピーして持つ。依存のパッケージから読まない。
  - コピーするのは、セマンティックトークンとテーマ変数が参照する値だけにする。
  - ファイルの冒頭に、コピーした元のパッケージとバージョン、出典の URL、MIT License の表示を残す。
- 名前は `--kufu-primitive-` で始める。出どころは、ファイルの中のコメントの見出しで分ける。
- motion の時間と緩急は、今の役割の名前と値を変えずに持つ。DADS は motion のトークンを持たない。

### 2. セマンティックトークンは、役割の名前を `--kufu-color-` で始める

- 種類は、面、文字、枠、操作、フォーカス、状態にする。shadcn の語彙（`background`、`foreground`、`muted`、`card`、`popover`、`sidebar-*`、`chart-*`）は使わない。
- 使っていない名前を残さない。名前を足すのは、使うコンポーネントか画面を足すときにする。
  - 状態の色は、エラー（`danger` と `danger-surface`）だけを置く。成功と注意は、使うコンポーネントを足すときに置く。
- 入力欄と押せるものの枠（`border-field`）は、面に対して 3:1 以上の色に当てる。飾りの区切りの線（`border`）は、今の `gray-300` のままにする。
- `gray-500` の文字は、暗い面だけで使う。明るい面の補足の文字は `gray-600` に当てる。
- `color-mix()` で作る 4 つの値（写真への被せ、写真の上のパネル、ウォーターマークの数字、副の面の hover）は、プリミティブトークンに近い値がないので、セマンティックトークンに値を直に持つ。
  - コントラストのチェックの組に入れる。ウォーターマークの数字は読ませる文字ではないので、組から外し、理由をトークンの文書に書く。
- 画面のコードは、プリミティブトークンの名前のユーティリティ（`text-kufu-gray-200` など）を書かない。暗い面の文字と面にも、役割の名前を付ける。

### 3. 暗い面は、スコープでセマンティックトークンの参照先を替える

- `.surface-inverse` のスコープの中で、面、文字、枠のセマンティックトークンの参照先を替える。画面とコンポーネントのコードに、面ごとの条件を書かない。
- コントラストのチェックは、`:root` と `.surface-inverse` の 2 つの条件で流す。
- ダークモードは作らない。`.dark` のブロックは消す。

### 4. テーマ変数は、Tailwind CSS のデフォルトを消す

- スタイリングは Tailwind CSS v4 のまま書く。
- `@theme inline` で、Tailwind のデフォルトの色、文字の大きさ、角丸、影、ブレークポイントを消し、置いた名前だけを使えるようにする。
  - 文字は、DADS の文字の大きさと行高から、用途の名前の付いたスタイルを置く。
  - ブレークポイントは、今の実装が使う幅だけを置く。DADS が基準にする 768px を含める。
  - 余白は、Tailwind のデフォルトの段（1 段 4px）を使う。DADS は余白の絶対の値を決めていない。
- フォーカスの表示は、`theme.css` に 1 つのユーティリティ（`focus-ring`）として置く。
- 動きを減らす設定のときの止め方は、`theme.css` の 1 か所に置く。

### 5. チェックを、パッケージ design-system のスクリプトで流す

- 3 つのチェックのスクリプトを、ルートの `scripts/` に置き、手元と CI で流す。
  - `check-contrast.mjs`: コントラスト
  - `check-raw-values.mjs`: 色の値と、プリミティブトークンの名前
  - `check-utilities.mjs`: 原則に反するユーティリティ
- `apps/corporate-site/scripts/check-token-usage.mjs` は、`check-raw-values.mjs` に置き換えて消す。

### 6. `packages/ui` の CSS の entry は、`theme.css` と `fonts.css` の 2 つにする

- `theme.css` が `semantic.css` を、`semantic.css` が `primitive.css` を読む。使う側は、`tailwindcss` の後に `@kufu/ui/theme.css` を読む。
- `fonts.css` は、今と同じく document の head から読む。
- `./tokens.css` と `./styles.css`（shadcn の層を含む全量の entry）の export を消す。

この決定は、ADR-0007 を置き換える。承認したときに、ADR-0007 の Status を「ADR-0027 に置換」にする。

## Considered Options

| 選択肢                                                                                          | 強み                                                                                                            | 弱み                                                                                                                  |
| ----------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **採用:** Kufu の色を残し、状態とフォーカスと文字と角丸と影を DADS からコピーし、3 つの層で持つ | Kufu の色が変わらない。buddy、fukuemon.dev と同じ層の名前と、同じチェックのスクリプトを使える。使う値だけを持つ | プリミティブトークンの出どころが 2 つになる。Kufu の色の組み合わせは DADS の指針に頼れず、チェックで確認する          |
| グレーも DADS の solid-gray に替え、teal だけを残す                                             | グレーの組み合わせを DADS の指針に頼れる                                                                        | 寒色のグレーが無彩色になり、Kufu の色が変わる                                                                         |
| `@digital-go-jp/design-tokens` を依存のパッケージから読む                                       | DADS の修正を、バージョンを上げて取り込める                                                                     | 使わない値も全て読む。buddy、fukuemon.dev と持ち方が分かれる                                                          |
| 今の 2 層のまま、shadcn の語彙の名前だけを改める                                                | 変更が小さい                                                                                                    | テーマ変数の層がなく、Tailwind のデフォルトの色と文字の大きさを画面のコードで書ける。チェックが前提にする形と合わない |
| shadcn の語彙を残す（ADR-0007 のまま）                                                          | 260 か所を付け替えずに済む                                                                                      | shadcn を外すと、使わない名前を残す理由がなくなる。運営者の決定と合わない                                             |

## Consequences

### Positive

- 画面のコードは、テーマ変数のユーティリティだけで書け、Tailwind のデフォルトの色と文字の大きさを書けない。
- コントラスト、色の値、小さすぎる文字、フォーカスの表示の上書きを、CI で確認できる。
- 3 つのリポジトリで、同じスキルと同じ層の名前でトークンを扱える。

### Negative

- shadcn の語彙のユーティリティの 260 か所と、プリミティブトークンの名前のユーティリティを、新しい名前に付け替える。
- DADS の修正を取り込むときは、差分を読んで手でコピーする。
- 暗い面の条件があるので、コントラストのチェックを 2 つの条件で流す。
- テーマ変数を足したときは、チェックが新しい名前を受け付けることを確認する。
