# ADR-0036: エビデンスを、Playwright の録画と字幕で撮る

## Status

承認

## Context

- 画面の変更の確認は、スクリーンショットを手で撮って pull request に貼っている。
- agent-harness のパッケージ capture のスキル playwright-capture は、Playwright の録画に字幕を重ねてエビデンスを撮る。撮影の設定と字幕の関数の 2 つのファイルを、利用者のリポジトリに写して使う。
  - 撮影の設定は E2E の設定を読み込み、`-c` で渡したときだけ録画する。
  - 字幕の関数を使う spec は、撮影の設定を付けずに流すと、字幕を出さずに E2E として動く。
  - 既にある spec は、書き換えずに撮影の設定で流せる。録画には、字幕が出ない。
  - 撮るアプリの URL は、E2E の設定の `baseURL` で決まる。改修前のアプリを撮るときは、環境変数 `BASE_URL` で上書きする。
  - 録画を mp4 にまとめるスクリプトは、スキルのディレクトリにある。ffmpeg を使う。
- E2E の設定は、向ける先を環境変数 `E2E_BASE_URL` で受け取る。
- スキルのディレクトリは apm が配置し、Git で追跡しない。
- agent-harness は private のリポジトリで、このリポジトリは public である。
- 撮影の仕組みは、Playwright 1.64 以上が要る。
  - ADR-0034: [Playwright を 1.64.1 に上げる](0034-playwright-upgrade.md)
- E2E は、workspace の package にする。
  - ADR-0033: [E2E をルートの e2e/ に置いたまま、workspace の package にする](0033-e2e-workspace-at-root.md)

## Decision

- エビデンスは、E2E の spec を撮影の設定で流して撮る。
- 撮影の設定は `e2e/playwright.capture.config.ts` に、字幕の関数は `e2e/tests/fixtures/caption.ts` に写してコミットする。
  - 運営者が、private の agent-harness の 2 つのファイルを、public のこのリポジトリに写すことを認めた。
- 撮影の出力（`e2e/evidence/`）は、Git で追跡しない。
- E2E の設定の `baseURL` は、環境変数 `BASE_URL` で上書きできるようにする。`BASE_URL` を渡したときは、app を起動しない。
  - 今の `E2E_BASE_URL` は、`BASE_URL` に改める。向ける先を渡す名前を 1 つにするためである。
- 録画を mp4 にまとめるスクリプトは、スキルのディレクトリのものを使い、写さない。撮る人は、apm でスキルを配置し、ffmpeg を入れておく。
- 字幕を付けるのは、検証のシナリオの spec と、pull request の動作確認の spec だけにする。回帰の E2E の spec には付けない。

## Verification

2026-11-11 に、develop の b6b3fe4 を build して preview で配信し、Playwright 1.64.1 で確認した。macOS の手元の結果である。

- 撮影の設定で `smoke.spec.ts` を書き換えずに流すと、5 件が通り、テストごとに録画ができた。
- 字幕の関数を使う spec を 3 本書いて撮ると、mp4（H.264、1600x900）と判定の静止画ができた。
  - JavaScript を無効にしたテストでも、字幕が出た。
  - viewport を 390x900 にしたテストでも、字幕が出た。
  - 同じ spec を、撮影の設定を付けずに流すと、E2E として 3 件が通った。
- Git で追跡しない下書きのディレクトリに置いた spec を、`e2e/` の依存で流せるかは、確認していない。

## Considered Options

| 選択肢                                                                                                                             | 強み                                                                                   | 弱み                                                                                           |
| ---------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| **採用:** 撮影の設定と字幕の関数を写し、E2E の spec を流して撮る。向ける先は `BASE_URL` で渡し、字幕は検証と動作確認の spec に限る | 検証のシナリオと pull request の動作確認を、同じ仕組みで撮れる。撮る手順が spec に残る | 写したファイルの更新は、手で取り込む。mp4 にまとめるには、apm で配置したスキルと ffmpeg が要る |
| mp4 にまとめるスクリプトも、リポジトリに写す                                                                                       | apm を使えない人も、mp4 を作れる                                                       | 写すファイルが増える                                                                           |
| スクリーンショットを手で貼り続ける                                                                                                 | 何も足さない                                                                           | 操作の流れを録画で見せられない。確認の手順が人によって違う                                     |
| ブラウザを操作する別のツールで録画する                                                                                             | Playwright を上げずに済む                                                              | E2E の spec と別に、撮る手順を持つ。字幕と判定の静止画を、同じ形で残せない                     |

## Consequences

### Positive

- 字幕つきの spec は、撮影の設定を付けなければ E2E として動く。撮るためだけのコードを持たない。
- 改修前と改修後を、同じ spec で撮って比べられる。

### Negative

- 撮影の設定と字幕の関数を、このリポジトリに写して持つ。
- 録画には、ffmpeg と、apm で配置したスキルが要る。開発の準備に足す。
- 環境変数の名前が変わる。
